PaperScope

A place for the things I’m learning.

I often study several subjects at once. Lecture slides and notes keep arriving, while the same reference book may be useful in more than one course. I started PaperScope to organise, reuse and look up those materials over time.

I also want to ask questions about what I’m reading and check where the answers come from. That makes evidence and the state of the source material central to the project.

Built with

Python · FastAPI · PostgreSQL / pgvector · Next.js · Ollama · DeepSeek API · Docker · GitHub Actions

Development note 01

A real citation isn’t always enough.

In a set of synthetic test materials, the retry delay was 2 seconds in the test environment and 5 seconds in production. The model returned the right numbers, but its citations only described the environments. They did not include the numbers needed to verify the answer.

My original check could establish that a quotation appeared in the source. It could not establish that the quotation supported the claim being made.

I kept the verbatim quotation check and added citation-coverage checks for some time quantities and percentages, with one targeted correction attempt. I also tried a more complicated prompt structure. It made some examples worse, so I reverted it.

Where it stands

The fixed cases have improved. Live API calls still show structural failures, relevance misjudgements and repeated items. This is a narrow improvement, not a claim that hallucinations are solved, and I do not have a measured accuracy figure to report.

Development note 02

The source was gone. The answer was still on its way.

I reproduced a timing problem in a test: a user starts a question, then moves its source material to the recycle bin while the model is still generating an answer. By the time the answer returns, the material is no longer available for that question.

I record the material’s version when the request begins. Before saving the result, I check its status, version and topic membership again. If any of those have changed, I reject the late result.

The model can take time to respond, so I avoid holding a database transaction open throughout inference.

Where it stands

Tests verify that a late draft is not saved after its source is recycled. The inference that is already running cannot currently be cancelled.

A few other choices

What I’m keeping separate.

One source, several courses

Materials exist independently of courses. The week and purpose sit on the course–material link, so the same source can be reused in different contexts.

Keep sources and generated content separate

AI-generated content does not automatically become evidence for later questions. I want to avoid treating a previous answer as if it were an original source.

Some features can wait

I have deferred automatic question generation and marking to avoid reusing incorrect content. The immediate focus is the material and evidence behind an answer.
